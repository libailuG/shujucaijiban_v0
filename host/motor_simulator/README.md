默认离线；启动、刷新列表、离线注入均不打开串口。只有用户选择具体串口并点击“打开串口”后，才接收请求并反馈。左右各用独立线程，可仅开一路。此目录独立于真实主板工程。

## 界面操作

1. 保持离线，编辑两路反馈 ID、7个常规浮点字段、error_flag、1004磁编位置、1005四个参数。点击应用。整数接受十进制或0x十六进制；范围uint32，浮点必须有限且可表示为float32。
2. 下方模式选择配合“离线注入一帧”只在内存编解码，结果写入有界日志，不会往串口写。离线注入不计入真实串口统计。
3. 刷新串口，给需要使用的通道明确选择COM，默认2000000。打开前应用参数，左右不得选相同端口。未使用的一路保持离线即可。
4. 打开后可应用新反馈参数/ID；下一请求使用新设置。设置只是本地模拟器配置。关闭不发送额外停止命令；退出通知线程关闭并等待，不强制终止线程。
5. RX统计有效下行帧（含ID不匹配），TX统计完整写入的反馈，mismatch是静默忽略数，errors是串口/运行异常，discarded是重同步丢弃字节，bad_tail是坏尾候选数。最近命令保留全部字段。统计每次重新打开归零。每100ms刷新；每路待显示事件最多200条，日志最多1000行，高负载会丢弃旧日志，收发计数仍累计。

## 实际连接

软件不能凭空产生COM。需要支持 **2Mbps、二线半双工、自动方向切换** 的USB转RS485适配器；两路独立同时模拟需要两个独立COM（两个适配器或双通道适配器）。普通USB-TTL不能直接接A/B。本程序不控制DE GPIO，不实现依赖RTS的软件换向；适配器换向与主板接收窗需实际验证。

- 左模拟器 ID126：PC适配器A → 主板JP3的2脚A；B → 3脚B；信号地按适配器隔离/接地要求接1脚DGND。JP3对应USART3。
- 右模拟器 ID127：另一PC适配器同样接JP2的2脚A、3脚B，地参照1脚DGND。JP2对应USART6。
- JP2/JP3的4脚是+5V，保持不连接USB适配器供电端，避免供电冲突；端接电阻按线缆实际两端及已装情况处理，不凭软件假定已装。
- 在拟模拟链路上断开真实电机，避免相同ID同时应答。保留板卡现有2Mbps、8N1、无流控设置；当前主板每5ms发送mode0。
- 可只接JP3并仅打开左通道。若只有一根适配器，不把两路主板独立总线并接为一条。

选择COM并打开后，匹配ID的每个完整请求回复一个48字节反馈。观察RX/TX增长、mode0、反馈参数与主板接收结果。ID错误静默，不主动心跳。2Mbps适配器及换向时序的真实表现尚未验证，PC/Python不是硬实时设备，不能保证5ms截止时间。3Mbps保留为可选值，已知板卡3Mbps失败，联调保持2Mbps。

## 模拟语义与边界

固定小端`<III7fII`，48字节。下行AA/EE，上行BB/DD，无CRC或序号。流解析支持半包、粘包、垃圾及坏尾重同步；头尾验证不等价内容校验。C6的`<III8fI`以及monitor的36字节遥测完全不混用。协议无CRC，若其他协议字节恰好符合头尾，不可能仅靠帧结构可靠区分，必须选择正确串口。

- mode0、1、11：返回用户设定的常规固定反馈，不跟随指令运动，不计算PD或任何动力学。
- 普通KP是电流系数；KD是速度Kd。普通单位为N·m、rad/s、rad、℃。
- mode1004：仅将torque替换为用户配置的第二编码器磁编位置，单位、范围及回绕规则未知。
- mode1005：前四个浮点依次返回配置的扭矩系数、电流环Kp/Ki/Kd。
- mode2、1000、1002、1003、1006及未知模式：仅记录完整请求、返回固定反馈并回显mode；不执行置零、校准或写参。1002/1003请求error_flag是磁值，日志原样保留；1006请求前四float是写参数据，仅观察。
- mode1001：motor_id只含目标新ID，没有旧ID。仍执行严格ID匹配；不匹配静默，匹配时返回固定反馈，**不修改模拟ID**。不假设广播改所有电机。

所有响应都是模拟策略，mode回显不是厂家保证；没有专用ACK/NACK，未定义特殊命令执行成功状态，不根据返回帧编造成功判据。反馈error_flag始终是配置原值，不定义错误位。参数改动不落盘，重启恢复默认值。
