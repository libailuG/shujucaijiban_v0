二、线上结构与命令
默认3000000 baud，8N1、无流控（serial.Serial未覆盖默认配置）。
小端，uint32_t及IEEE754 float32；固定48字节，Python格式 <III7fII。
不含CRC、累加和、序号、长度或事务号。帧头尾匹配只能确认候选帧边界，不能证明内容无误。

偏移/类型/名称：
0  u32 start_flag；4 u32 motor_id；8 u32 mode；
12 f32 torque；16 f32 speed；20 f32 ang；24 f32 temp_board；
28 f32 temp_motor；32 f32 KP；36 f32 KD；40 u32 error_flag；44 u32 end_flag。
主板到电机：AAAAAAAA / EEEEEEEE；电机到主板：BBBBBBBB / DDDDDDDD。
常规单位：torque N·m，speed rad/s，ang rad，温度℃。
rpm和度只在上位机显示端由speed*30/pi、ang*180/pi换算。

下列“其余清零”均不包括帧头、帧尾、motor_id、mode：
mode 0：停止，其余清零。
mode 1：位置/扭矩，传torque、speed、ang、KP、KD，其余清零。
mode 11：速度，传speed、KP、KD，其余清零。
mode 2：关节零点校准，其余清零。
mode 1000：FOC校准，其余清零。
mode 1001：改ID，motor_id直接是目标新ID，其余清零；没有旧ID字段。
mode 1002/1003：X/Y磁校准，error_flag是磁值，GUI限制0..255，其余清零。
mode 1004：第二编码器观测请求，其余清零。
mode 1005：读电流参数，其余清零。
mode 1006：写电流参数，torque=扭矩系数、speed=电流环Kp、ang=电流环Ki、
temp_board=电流环Kd；temp_motor、KP、KD、error_flag清零。
反馈mode=1005也用上述前四个float映射参数，上位机收到后将周期发送状态改为停止。
正弦扭矩仍是mode=1，上位机计算A*sin(2*pi*t/T)，speed、ang为0，KP/KD沿用输入。
内部motor_control_enable=2映射线上11；不能把内部枚举2直接发给电机。

原说明需补充/限定的点：
1. mode1004：源码1985..2025的校准检查把torque显示框当作第二编码器角度(rad)读；
   显示框本身来自反馈torque（1134行）。提示该模式可能复用torque字段，
   但它没有核对该样本mode/ID及新鲜度，因此不能把这一使用方式当作固件已确认定义。
   接收应保留原始全部字段，1004专用解释暂缓，不直接拿ang代替关节角度。
2. GUI初始当前ID126，一键校准左右选择126/127（1617行）；只是生产工具约定，
   不是已读取的实际ID，也不是有效ID上限、广播ID或板卡左右接口的映射证据。
3. 生产流程含改ID、磁/零点/FOC校准及正反扭矩运行检查；不应作为接入自检运行。
   其中15秒等待、波动阈值等是GUI流程启发式判断，不是固件应答规范或校准耗时保证。
4. GUI按钮停控只改本地状态，实际由下一次10ms定时器发送；关闭/退出会另尝试发停止。
   发送成功返回不等同电机执行成功（write返回长度亦未核对），不能照搬成ACK判据。

源码定位：211..217默认速率；2198..2406结构体；2419..2504流解析；
2575串口打开；2902..2947上下行定义；3088..3221特殊命令；3236..3288周期映射；
3337..3339发送10ms。100Hz是PC名义发送频率，不能据此认定反馈100Hz。

三、板卡接线候选（原理图第2/3/4页交叉核对）
板上8路XL485-SS，各自一个独立串口、方向GPIO和A/B接口；图纸标为“IMU”。
是否允许挪用、哪路已接设备需确认，不能单凭空闲源码判定接口空闲。

接口  图纸名称  串口      TX   RX   RE#/DE GPIO 收发器 终端电阻位
JP2   左IMU1   USART6    PC6  PC7  PC8         U8     R30
JP5   左IMU2   USART1    PA9  PA10 PA11        U9     R31
JP8   左IMU3   UART8     PE1  PE0  PB9         U12    R46
JP11  左IMU4   USART10   PE3  PE2  PE4         U13    R47
JP3   右IMU1   USART3    PD8  PD9  PD10        U10    R38
JP6   右IMU2   UART5     PB13 PB12 PB14        U11    R39
JP9   右IMU3   UART7     PE8  PE7  PG0         U14    R54
JP12  右IMU4   USART2    PA2  PA3  PA6         U15    R55

上述每个RS485接口均：1 DGND；2 A；3 B；4 +5V（左+5V_V2，右+5V_V3）。
4脚是图示5V输出，不能据此当电机功率电源，也不能接外部高压电机电源。
电机A/B/GND及接口供电脚定义需先核对；板卡有RS485不证明电机就是RS485。
板上收发器供电+3.3V_RS485或V2；每路A上拉1k、B下拉1k，RO另有1k上拉。
终端位标120/1%/NC，表示设计预留不装；需实物确认，不应按已装120Ω计算。
布线若采用总线，终端应按物理两端处理，避免所有节点均装终端；线缆/电机内置终端待查。
XL485-SS准确速度等级、使能/禁能延时与板上实装型号仍需器件资料核验，不能因串口可3M就保证收发器可用。

RE#与DE同网：按图纸信号逻辑，低=接收使能/驱动关闭，高=发送使能/接收关闭。
建议首版软件GPIO控制方向；引脚AF与USART硬件DE支持应逐路查STM32H723ZGT6复用表，
上表只列图纸连接，不把网名当作AF证明。不要复用为单线UART HDSEL模式。
初始化先设置方向输出锁存为低，再切GPIO输出，保持接收；具体上电毛刺以板测确认。

JP7是预留串口2：UART9，PD15 TX/PD14 RX AF11，1地/2RX/3TX/4为3.3V。
当前C6已占用，921600 8N1；不是USART2，也没有直接接XL485。
JP4则是UART4 TTL预留口，不在上述8路RS485表内。

四、3Mbps与时序计算（设计值，尚无示波器实测）
实际系统HSE25MHz，CPU550MHz、HCLK275MHz、APB1/2=137.5MHz。
按PCLK作为UART内核、PRESC=/1、16倍过采样：BRR四舍五入为46，
137500000/46=2989130.435 baud，误差-0.362319%；BRR45约+1.85185%，不优先选。
不能使用定时器APB翻倍275MHz作为UART时钟；8倍过采样也不会自动消除整数分频误差。
参考ST UM2217的LL_USART_SetBaudRate说明：
https://www.st.com/resource/en/user_manual/um2217-description-of-stm32h7-hal-and-lowlayer-drivers-stmicroelectronics.pdf
此误差只是本端名义分频误差，能否可靠通信还取决于电机晶振、接收容差和线缆。
无需为精确3M立即改PLL。未来若更换内核时钟，须评估共享时钟组：
USART1/6/UART9/USART10共用选择；USART2/3/UART4/5/7/8为另一组。
reserved_uart2_init会清USART16910SEL选PCLK2，不能让后续电机初始化改该组而破坏C6速率。

3M 8N1：每字节10bit=3.333us；48字节=160us（本端BRR46实为160.582us）。
一问一答纯线时约320us，未包含方向切换、传播、固件响应延迟。
100Hz一来一回占3.2%线时；同总线N电机约N*320us/10ms，前提是每命令仅一应答且无主动上报。
图纸8路是8条独立物理链路，不是自动共用一条总线；先单路单电机，暂不定义多机轮询策略。
发送：确认总线状态→DE拉高→等待芯片使能稳定→发送48字节→UART TC确认最后停止位完成→
DE拉低→接收应答。DMA完成、TXE都不能代替TC。转换等待值必须依据芯片数据和实测，不能任意填数。
保持RX路径预置，避免切回接收时丢首字节；应答等待窗/重试策略需按反馈行为确认。

五、驱动与应用接入方案（尚未加入工程）
1. motor_protocol.h/c：独立MotorFrame结构，字段和上方偏移一致；静态检查float/u32为4字节、
   总长48和各偏移。编解码显式小端读写，浮点用memcpy位转换，避免未对齐强转或严格别名问题。
   为下行和上行分别校验标记；编解码不负责自动发送，不填默认ID或非零增益。
2. motor_stream：搜索BBBBBBBB，够48字节检查44位置DDDDDDDD，尾错逐字节重同步；
   无头时保留可能的最多3字节头前缀。支持任意分包、粘包、垃圾、回显、错位。
   ORE/FE/NE/PE、DMA丢字节或缓冲溢出时清解析状态并计数，避免跨已知丢失拼帧。
   接收后按配置ID分发，保存完整原始反馈、mode、接收时间、计数、新鲜度；未知错误位原样保留。
   无CRC场景应用层仍需finite、ID/mode和合理范围审查；范围未约定前不编造限幅。
3. motor_bus：每个物理通道独立方向/发送缓冲/接收流/统计状态；非阻塞TX、TC切方向。
   初版保持发送禁用，先离线注入数据验证；接入时再按已确认接口启用单路。
   优先考虑DMA循环接收+IDLE/半满/全满处理（IDLE不是帧边界）；若选中断FIFO需测峰值负载。
   3M连续流最高300k字节/s，1024字节缓冲仅约3.4ms，不可只按平均100Hz设计。
   H723 DMA要选可访问SRAM，D-cache需非缓存区或正确维护及对齐；先查链接映射再实现。
4. motor_service：主循环有预算解析，独立周期调度，不在TIM7/I2C中断里发帧或阻塞等回包。
   可参考PC的10ms调度，但跳过错过的周期，不积压历史控制命令；应答/超时状态独立管理。
   特殊命令使用明确事务，普通反馈不视作所有命令ACK；掉线停止策略需先确认固件行为。
5. 保留TIM7的1ms IMU触发、I2C4 PD12/13、主循环姿态解算；保留PF11 ADC1 100Hz电池采样、
   TIM6 PG9四档灯、PC12/PC11/PB4按键。DMA/中断优先级不得挤占IMU时序。
6. C6业务帧虽同为48字节，却是<III8fI，双向AA/EE；电机是<III7fII且上下行标记不同。
   分开头文件、状态与串口，不能复用mcu_uart_protocol的解包逻辑或直接透传解释为电机命令。
   C6保持20Hz、data3电压V/data4 Roll rad/data5 Pitch rad，其余字段不自行映射。
   未来需另外定义C6命令语义、目标通道/ID、有效期和使能状态后再映射，当前下发仅存储。

八、用户后续确认及实施约束（2026-11-11）
1. 电机收到一帧命令回复一帧；ID不匹配不会回复。按请求/响应组织通信，
   不再把反馈是否主动周期上报列为未知；确切回复延迟与换向裕量仍待测。
2. mode=1004时，反馈torque字段确实承载第二编码器磁编位置。
   该模式不能把此字段当扭矩，也不能以普通ang字段替代；保留原始字段并按模式解释。
   用户确认的是磁编位置的字段语义，未补充该模式专用的位置单位、范围或回绕规则。
3. 左电机ID=126，右电机ID=127。保留mode1001设置ID命令供后续使用，当前不执行改ID。
   错误ID静默无回复；无回复不能单独断言为断线。共线改ID的目标选择规则尚未补充。
4. 下发控制指令中的KP用作电流系数设置，不是传统位置比例增益；
   KD是传统意义的Kd，用于速度控制。不得套用传统位置PD公式解释KP。
   mode1006中的speed/ang/temp_board仍分别是电流环Kp/Ki/Kd参数，
   与普通控制帧偏移32的KP电流系数分开命名，避免混淆。
   电流系数的数值换算、单位及允许范围尚未补充，不自行选择动作参数。
5. 用户要求现阶段先不处理断线和故障：暂不实现自动断线停机、故障恢复、错误位策略。
   UART收发错误清除、流解析重同步等底层通信正确性措施仍属于正常接收实现，
   不把未收到回复自行转换成电机动作指令。
6. 特殊命令没有专门反馈帧，只能通过返回的状态判断；统一使用既有48字节反馈格式。
   不增加或假设专用ACK/NACK帧；收到普通帧本身不等于特殊命令执行成功，
   需按该命令预期状态观察。具体各命令状态变化判据尚未逐项提供。
